# SentinelOT — Live Demo Script

## Before the demo
1. Run the full startup command block (see README or PROJECT_STATUS.md).
2. Confirm OpenPLC is Running (http://localhost:8090 via plc-relay).
3. Open http://localhost:3000 -- dashboard should show all devices as
   "Normal", no open alerts, green live indicators pulsing.
4. Have a second terminal ready, open to:
       tail -f ~/sentinelot/zeek-lab/real-sensor/logs/zeek/modbus.log

## The demo, step by step

### 1. Show the baseline (30 sec)
"This dashboard is live right now -- watch the timestamp update every
3 seconds. These are 6 real devices on a real network: a PLC speaking
four industrial protocols, an operator HMI, an IIoT sensor, and clients
for S7comm, DNP3, and OPC-UA. All showing Normal -- no attacks yet."

### 2. Trigger a real, on-the-spot attack (30 sec)
Run:
    ~/sentinelot/validation/trigger_demo_attack.sh
"I'm sending one real Modbus write command from a brand-new device on
the network, right now, live -- not a script that already ran, not a
pre-recorded alert."

### 3. Show the raw capture happening (live, in the second terminal)
Point to the terminal running `tail -f modbus.log` -- a new line
appears showing WRITE_SINGLE_REGISTER, in real time.
"This is Zeek, the same tool real security teams use, genuinely
watching this happen on the wire."

### 4. Show the alert appear on the dashboard (within ~5-10s)
The device's card on the dashboard turns from Normal to a red/orange
alert badge automatically -- no page refresh needed.
"No one clicked anything on the dashboard. It updated itself because
the detection pipeline caught this independently."

### 5. Expand the alert -- explain the detection chain
Click "View alert details":
- Point to "Detected by: Zeek -- behavioral rule (first-ever write)"
  "This specific device has only ever read data before. The moment it
  wrote for the first time, our rule caught the behavior change."
- Point to the plain-language explanation
  "This sentence was generated by a local AI model running entirely on
  this laptop -- no internet, no API cost -- specifically so a
  non-technical plant operator can understand it without training."

### 6. Show independent confirmation (Suricata)
"A second, completely independent detection engine -- Suricata,
signature-based, a different technique entirely -- also caught this
same event. Two different methods agreeing is stronger evidence than
either alone."
(Optional: show eve.json if time allows)

### 7. Acknowledge/resolve it live
Click "Resolve" on the alert -- it disappears from Open Alerts.
"An operator can triage and close this the same way a real SOC
dashboard works."

### 8. Show History & Trends
Switch tabs. "This is the full historical record -- every alert ever
recorded, with real charts, clearly separated from the live view so
past and present are never confused."

### 9. Show the compliance report
Click "Compliance Report" link. "Auto-generated from the same real
database, structured around CERT-In's incident categories."

### 10. Mention validation (if asked "is this really detecting attacks?")
"We validated this exact parser against the CIC Modbus Dataset 2023,
a published research dataset from the University of New Brunswick --
152,251 real, independently-created Modbus transactions, correctly
parsed. See validation/RESULTS.md."

## If something doesn't work live
Stay calm, say so plainly: "This is real infrastructure, and like any
real system it can have a hiccup -- let me show you the raw logs
directly instead" and fall back to `docker logs <container>` or the
log files directly. A staged demo never has anything to fall back to;
a real one does.
